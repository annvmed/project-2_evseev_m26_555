# Primitive DB

Простая консольная база данных на Python. Хранит метаданные таблиц и записи в JSON-файлах, поддерживает создание и удаление таблиц, а также полный набор CRUD-операций над записями.

Проект выполнен в рамках курса Python-разработчик (Яндекс Практикум) и демонстрирует работу с пакетным менеджером uv, файловой системой, парсингом пользовательского ввода, декораторами и замыканиями.

## Технологии

- Python 3.12
- uv — управление зависимостями, виртуальным окружением и сборкой пакета
- prettytable — форматированный вывод таблиц в консоль
- prompt — удобный ввод с повторным запросом при пустом вводе
- ruff — линтер и форматтер (dev-зависимость)
- Стандартная библиотека: json, shlex, os, time, functools, re

## Управление таблицами

Команды:

- create_table <имя> <кол:тип> ... — создать таблицу. Автоматически добавляется ID:int
- list_tables — показать список всех таблиц
- drop_table <имя> — удалить таблицу (с подтверждением)
- help — справка по всем командам
- exit — выход из программы

Поддерживаемые типы данных: int, str, bool.

Пример:

    Введите команду: create_table users name:str age:int is_active:bool
    Таблица "users" успешно создана со столбцами: ID:int, name:str, age:int, is_active:bool

    Введите команду: list_tables
    - users

    Введите команду: drop_table users
    Вы уверены, что хотите выполнить "удаление таблицы"? [y/n]: y
    Таблица "users" успешно удалена.

## CRUD-операции

Команды:

- insert into <имя> values (<v1>, <v2>, ...) — добавить запись. ID генерируется автоматически
- select from <имя> — показать все записи
- select from <имя> where <col> = <val> — фильтрация по условию
- update <имя> set <col> = <val> where <col> = <val> — обновить записи
- delete from <имя> where <col> = <val> — удалить записи (с подтверждением)
- info <имя> — информация о таблице: столбцы и число записей

Строковые значения обязательно заключаются в кавычки.

Пример:

    Введите команду: insert into users values ("Sergei", 28, true)
    Запись с ID=1 успешно добавлена в таблицу "users".
    Функция insert выполнилась за 0.001 секунд.

    Введите команду: select from users where age = 28
    +----+--------+-----+-----------+
    | ID |  name  | age | is_active |
    +----+--------+-----+-----------+
    | 1  | Sergei | 28  |    True   |
    +----+--------+-----+-----------+
    Функция select выполнилась за 0.000 секунд.

    Введите команду: update users set age = 29 where name = "Sergei"
    Запись с ID=1 в таблице "users" успешно обновлена.

    Введите команду: delete from users where ID = 1
    Вы уверены, что хотите выполнить "удаление записи"? [y/n]: y
    Запись с ID=1 успешно удалена из таблицы "users".

    Введите команду: info users
    Таблица: users
    Столбцы: ID:int, name:str, age:int, is_active:bool
    Количество записей: 0

## Обработка ошибок и подтверждения

- Все ошибки бизнес-логики централизованно перехватываются декоратором handle_db_errors — пользователь видит понятное сообщение, программа не падает.
- Перед drop_table и delete запрашивается подтверждение [y/n]. Любой ответ, кроме y, отменяет операцию.
- Время выполнения insert и select логируется декоратором log_time.
- Неизвестные команды и некорректные значения аргументов выводят сообщение и повторно запрашивают ввод.

## Структура проекта

    project-2_evseev_m26_555/
    ├── src/
    │   └── primitive_db/
    │       ├── __init__.py
    │       ├── main.py         # точка входа
    │       ├── engine.py       # главный цикл и обработка команд
    │       ├── core.py         # бизнес-логика (таблицы и CRUD)
    │       ├── parser.py       # парсинг команд, where/set, values
    │       ├── utils.py        # работа с файлами
    │       ├── decorators.py   # декораторы и кэширование
    │       └── constants.py    # константы проекта
    ├── data/                   # данные таблиц (в .gitignore)
    ├── dist/                   # собранные дистрибутивы (в .gitignore)
    ├── pyproject.toml
    ├── uv.lock
    └── README.md

Данные хранятся в JSON:

- db_meta.json — метаданные таблиц (имена и схемы столбцов)
- data/<имя_таблицы>.json — записи соответствующей таблицы

Оба пути добавлены в .gitignore и не попадают в репозиторий.
